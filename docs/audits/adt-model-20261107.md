# Administrative ADT protocol extension — 2026-11-07

New ADT specifications and lock-order assumptions need owner review. The earlier
commit-protocol specifications/Postgres assumptions were approved on 2026-11-07;
this extension does not change those statements or the clinical Comparator.

## Implemented scope

`AdtModel.lean` reuses `Ehr.Commit.Adt.commit` for admit, assign, transfer,
release, discharge, clean and ready. It models arbitrary valid provisioned
baselines, actor-scoped immutable request intent, request reservation, incremental
closed-board locks, locked reads, expected-board checks, native administrative
guards, individual private stream UPDATEs, individual event INSERTs, request
outcome staging, atomic publication, response loss, crashes, timeouts and retries.
The read set and changed-stream write set are distinct. Versions advance only on
streams that changed. Transfer writes one patient plus source and destination
beds in one publication. Clean/ready change only a bed stream.

A logical transaction event represents the duplicated SQL event envelopes on
its changed streams. `HistoryCorrect` checks that duplication's exact stream set,
read versions and native transition against its prior log prefix. It does not
prove the JSON/FHIR transformer. The storage assumption remains primary READ
COMMITTED with transaction-held exclusive row/unique-key locks, consistent
provisioning, sole online writer, and atomic durable event/projection/receipt
publication. No intermediate private MVCC state is publicly observable.

Clinical placement can use the same machine: its fresh non-ADT guard and session
version/revision checks are explicit abstract inputs. The trace adapter computes
those checks from recorded fields. Administrative admission/placement guard
semantics execute the actual reducer, rather than a Boolean oracle.

The service and native command datatype contain **no swap or cancellation
operation**. HTTP tests reject `swap`/`cancel` with 400. Opposite transfers into
occupied beds fail the native guard. Crash/rollback is not an administrative
cancellation. This lane does not invent a new policy or silently label two
transfers as a swap.

## Kernel-checked statements

All names below are in `Ehr.Commit.Protocol.AdtModel`, except the lock lemma.
They quantify over arbitrary finite client/request lists and arbitrary numbers
of interleavings, crashes and retries from any valid baseline.

| Theorem | Statement |
|---|---|
| `machine_invariant` | Every `Reachable` machine has a valid native board, exact reducer fold, unique event request IDs, event/accepted-receipt correspondence, and correct historical guards/write sets. |
| `bed_exclusivity` | Two bed records in a reachable board with the same bed ID and occupants `p₁`, `p₂` imply `p₁ = p₂`. |
| `patient_one_bed` | Two beds occupied by a known patient in a reachable board imply equality of their bed IDs. |
| `projections_equal_fold` | Durable board equals the native `Adt.apply` fold of its accepted transaction log over the provisioned baseline. |
| `no_duplicate_accepted` | Accepted transaction event request IDs are duplicate-free, including multi-stream commands. |
| `retry_stable` | A matching durable receipt/payload yields the identical answer and unchanged durable state. |
| `receipt_persistent` | Publication of any other request preserves an existing receipt. |
| `changed_payload_no_effect` | A receipt with the same ID but different payload produces payload conflict and no state change. |
| `no_lost_accepted`, `no_phantom_effect` | Every accepted receipt has an event and every event an accepted receipt with matching ID/payload. |
| `guards_and_writes_on_replaced_versions` | Every accepted event has the exact prior version vector, a native accepted decision and all/only changed patient/bed stream keys. |
| `refusal_no_effect` | Fresh refused/stale requests change neither board nor log. |
| `partial_write_private` | An individual event INSERT step changes no durable field. |
| `advance_publication` | Each fine-grained machine step leaves durable state unchanged or performs one `publish`. |
| `LockOrder.no_wait_cycle` | No nonempty finite circular wait exists when every blocked transaction holds a prefix of a strictly increasing resource-rank plan. |

`publish_invariant`, `initial_invariant`, `decide_accepted`, `receipt_fresh` and
`LockOrder.wait_increases` are also axiom-audited. All new declarations use only
`propext`, `Classical.choice`, `Quot.sound` (or subsets); no new axioms or proof
holes. Protected specifications, properties, statements and comparator inputs
are unchanged.

The lock hierarchy inspected in the online service is request reservation →
optional session → distinct stream keys in C/ASCII sort order. An administrative
command acquires no session lock. One request and at most one session per
transaction permit a global rank by resource class and sorted stream key. This
is a **conditional ordered-prefix theorem**, not a proof that TypeScript/SQL
implements the hierarchy. The executable ADT checker also checks actual modeled
lock prefixes, mutual exclusion and absence of circular waits in each explored
state; traces check actual acquisition order. Provisioning/offline imports and
Postgres internal locks are outside that correspondence. There is no theorem
of fairness, eventual response, physical patient placement or starvation freedom.

## Bounded evidence

`AdtCheck.lean` first exhausts all reachable reducer boards for two patients,
two beds and all three administrative roles. It then exhausts transaction graphs
with fixed commands/expected vectors and up to three concurrent attempts. The
finite graphs contain repeated crashes, retries and timeouts with no depth
cutoff. Exceeding the explicit 150,000-state budget fails closed. Shortest BFS
paths are retained for counterexamples. Every reached transaction state checks
the durable semantic invariant and the lock invariant.

Five unsafe durable controls must fail: incorrect projection, missing receipt,
duplicate request effect, partial multi-stream write set, and inconsistent
placement. A two-resource reversed-acquisition control must detect a wait cycle.
No service bug was inferred from that intentionally unsafe control.

The final run exhausted **26,812 transaction states / 207,641 transitions**
across 12 scenarios, plus **62 reducer boards / 520 accepted transitions**.
Every graph completed without a safety or lock counterexample. All six negative
controls were detected. The existing protocol checker separately exhausted
21,393 transaction states / 167,298 transitions plus 81 cache states; its five
unsafe controls were rejected.

## Host refinement tests

`COMMIT_PROTOCOL_TRACE` remains opt-in test instrumentation. Administrative and
clinical placement traces include positional patient aliases preserving key
order, hashed unit names, numeric bed IDs, administrative board inputs/outputs,
versions, exact lock order, separate private UPDATE/event INSERT steps and
request outcome/COMMIT intervals. No credentials, chart values or native clinical
states are exported. This changes only test instrumentation, not command policy.

`model/check-adt-trace.ts` requires an explicit provisioned baseline before any
writer. It validates lock/order/pairing, changed-stream writes and stable response
hashes, then calls `AdtTrace.lean`. Lean searches for a transaction serialization
consistent with invocation/completion intervals, every observed board and every
locked version, executing the same `AdtModel.advance`. Uncertain COMMIT branches
between rollback and publication followed by lost reply. Missing/incomplete
traces, search-budget exhaustion and semantic mismatches fail. Hashes alone are
not treated as evidence of administrative fold correctness.

The administrative integration suite covers seeded admission and
transfer/discharge races across two replicas; release/assign/turnover;
whole-transfer rollback after earlier private writes; changed payload and
concurrent duplicate retries; and a real COMMIT whose reply is discarded and
recovered exactly once. Existing independent native journal/projection replay
remains active. Altered lock order, removed event writes and coherently falsified
board contents are required to fail. The clinical ADT integration suite includes
an administrative discharge on the same traced board and excludes its manually
seeded historical privacy envelope from the trace interval.

This is a transaction-linearized refinement **test**, not a theorem about Node,
SQL, actual overlapping lock timing, provisioning, FHIR projection semantics or
the completeness of the administrative policy.
