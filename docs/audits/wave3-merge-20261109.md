## Conflict resolution

- **wave3-sim over wave3-data.** The sim branch carried copies (`7a60c3c3`,
  `c627b3f5`) of the data lane's first two commits. Conflicted files were
  re-merged with `c627b3f5` as the base, so only the sim lane's own changes
  apply on top of the data lane's final `abed79c2`. Every sim-touched file was
  then compared with that 3-way result. The default merge had duplicated
  `NoteText` in `Core/Types.lean` and `generated/ehr-types.ts`; that was fixed.
  `synthetic-hospital.md` takes the sim lane's wording about length-dependent
  scroll and reading, because the sim lane implemented it.
- **wave3-workflows over the merged sim and data lanes.** Both sides are wave 3.
  - `Sim/Bounded.lean` and `Sim/Policy.lean` keep the sim lane's clinical-service
    offset and also subtract the workflow protocol time from `klmDeciSec`.
  - Timings apply `Workflow.withAdministration` inside `Scheduling.withClocks`.
  - Protocol active time is reported as clinical clock time, and the protocol
    response wait as passive wait. The clock partition therefore still sums to
    the task duration. This attribution is a merge decision; see the
    [method note](../methods/wave3-simulation.md#separate-time-on-one-server).
  - `Policy` keeps the sim lane's `legacyModel && fixedCost` KLM condition.
  - `Goals.lean` keeps the workflow alert-resolution branch and the data lane's
    `sectionText`.
  - `GenTS`/`sim-types.ts` take the union of both lanes' fields.
  - World generation: `--workflows` becomes `WorldOptions.workflows`. `DayBuild`
    takes `caseMix` and then `workflowMode`, and `startMin` keeps both lanes'
    unclamped cases.
- **lean-refactor.** None of its Lean files overlaps wave 3, so every refactored
  proof is kept and nothing was dropped. The FixedLineCompletion notation stays
  (owner decision). The refactor stays stopped at its branch content.
  `docs/proof-map.md` was regenerated after the merged build.

  explicit legacy configuration (`mode := .fixedCost, legacyModel := true`) and

  the legacy flows, matching the world-clock and case-mix convention. `world gen`

  because of the additive v2 `imagingPriority` element. The old hashes pass when
  main's `releases/v2,v3` are restored, so the hashes were refreshed. Nights 1–3
  (v1) are unchanged.

  `app/public/ehr/manifest.json`. The manifest had been stale since the refactor,
  because it hashes every `.lean` file. The native `ehr` binary is now
